# Status Monitor — Frontend (сайт)

Это **видимая часть** системы «Мониторинг состояний»: страница, на которой пользователь смотрит таблицу ID, статусы, время обновления и подробности событий.

Инструкция рассчитана на новичка. Она относится к ветке **`main`**, где frontend запускается отдельно от backend через npm, **без Docker**.

## 1. Что здесь находится

Система состоит из двух репозиториев:

| Репозиторий | Что делает |
| --- | --- |
| **[status-monitor-frontend](https://github.com/FoKuStNiK/status-monitor-frontend)** (этот) | Показывает страницу, фильтры и сообщения о подключении |
| **[status-monitor-backend](https://github.com/FoKuStNiK/status-monitor-backend)** | Хранит статусы в SQLite, принимает Webhook, предоставляет API и WebSocket |

Как всё связано:

```text
Внешняя программа
       |
       | POST /api/webhook
       v
Backend (Node.js, порт 5000) ----> SQLite (база состояний)
       |
       | API + WebSocket
       v
Frontend (React, порт 3000)
       |
       v
Браузер пользователя
```

Простыми словами:
- **Frontend** — интерфейс, который вы видите.
- **Backend** — сервер, который обрабатывает и хранит данные.
- **React** — библиотека JavaScript для интерфейса.
- **API** — способ запросить текущие данные у backend.
- **WebSocket** — соединение, через которое сервер сразу сообщает об изменениях.
- **npm** — инструмент для установки библиотек и запуска проекта.

**Важно:** один frontend без backend откроет страницу, но не сможет получить реальные состояния.

## 2. Что потребуется

Установите:
- [Git](https://git-scm.com/downloads) — чтобы скачивать и обновлять код.
- [Node.js](https://nodejs.org/) **версии 20 или новее** — вместе с ним устанавливается npm.

Подойдёт Windows (Git Bash или PowerShell), Linux или macOS.

Проверьте в терминале:

```bash
git --version
node -v
npm -v
```

Если команда не найдена, установите программу и откройте терминал заново.

## 3. Запуск с нуля: инструкция для новичка

Для полноценной работы нужны **два открытых терминала**: один для backend и один для frontend.

### Шаг 1. Скачать оба репозитория

В удобном для вас каталоге выполните:

```bash
mkdir status-monitor
cd status-monitor
git clone https://github.com/FoKuStNiK/status-monitor-backend.git
git clone https://github.com/FoKuStNiK/status-monitor-frontend.git
```

`git clone` скачивает код с GitHub. Если папки проектов уже есть, повторно скачивать их не надо.

Две папки должны выглядеть так:

```text
status-monitor/
├── status-monitor-backend/
└── status-monitor-frontend/
```

### Шаг 2. Запустить backend (терминал № 1)

Из общей папки:

```bash
cd status-monitor-backend
npm install
```

Создайте файл `.env` на основе `.env.example`:

**В Git Bash / Linux / macOS:**

```bash
cp .env.example .env
```

**В PowerShell:**

```powershell
Copy-Item .env.example .env
```

Выполнять нужно **одну** из двух команд — для вашего терминала.

Откройте созданный `.env` и замените значение `WEBHOOK_TOKEN=your-secret-token` на собственный длинный секретный токен. Остальные настройки можно оставить для локального запуска по умолчанию.

Теперь:

```bash
npm start
```

Backend должен работать на `http://localhost:5000`. Проверьте адрес [http://localhost:5000/api/health](http://localhost:5000/api/health): ожидается `{"ok":true}`.

**Не закрывайте этот терминал.** Подробности об устройстве backend есть в [его README](https://github.com/FoKuStNiK/status-monitor-backend/blob/main/README.md).

### Шаг 3. Запустить frontend (терминал № 2)

Откройте **новый терминал**. Из общей папки `status-monitor` выполните:

```bash
cd status-monitor-frontend
npm install
```

Создайте `.env` из `.env.example`, как в предыдущем шаге:

- Git Bash / Linux / macOS: `cp .env.example .env`
- PowerShell: `Copy-Item .env.example .env`

В файле должны быть следующие адреса для локальной разработки:

```dotenv
REACT_APP_API_URL=http://localhost:5000
REACT_APP_WS_URL=ws://localhost:5000/ws
```

Запустите сайт:

```bash
npm start
```

Обычно браузер откроется автоматически. Если этого не произошло, откройте [http://localhost:3000](http://localhost:3000) вручную.

**Итог:**
- `localhost:3000` — страница сайта.
- `localhost:5000` — backend, к которому обращается сайт.
- `localhost` означает тот компьютер, где запущена программа.

### Шаг 4. Добавить тестовые данные (терминал № 3)

При первом запуске таблица может быть пустой — это нормально: в базе ещё нет событий.

Откройте третий терминал, перейдите **в папку backend** и выполните:

```bash
npm run test:webhook
```

Скрипт создаст 50 тестовых событий для ID от 1 до 10. Увидите строки в таблице и их автоматические обновления. Backend должен продолжать работать.

Если для запуска backend используется нестандартный порт, этот тестовый скрипт по умолчанию всё равно обращается к `http://localhost:5000` — путь в скрипте потребуется изменить.

### Шаг 5. Остановить приложения

Чтобы остановить frontend или backend, перейдите в соответствующий терминал и нажмите **Ctrl + C**.

При следующем запуске из каждой папки можно просто выполнить `npm start`: повторное клонирование не нужно.

## 4. Что умеет интерфейс

- **Таблица состояний:** ID, текущий статус и время его обновления.
- **Фильтр по ID:** показать одну конкретную запись.
- **Фильтр по статусу:** показать только записи с нужным статусом.
- **Одновременные фильтры:** можно использовать ID и статус вместе, а затем сбросить фильтры.
- **Подробности:** нажмите на строку таблицы, чтобы показать `details`. Можно раскрыть несколько строк одновременно.
- **Обновления без перезагрузки:** WebSocket приносит новые записи с backend.
- **Восстановление соединения:** после обрыва сайт пытается переподключиться, а после восстановления загружает актуальные данные.
- **Светлая/тёмная тема:** выбранная тема сохраняется в браузере.

Данные не появляются автоматически из воздуха: их должен получить backend через Webhook либо тестовый скрипт.

## 5. Как frontend получает данные

При открытии страницы React делает запрос:

```text
GET http://localhost:5000/api/statuses
```

Backend возвращает список записей. Затем React подключается к:

```text
ws://localhost:5000/ws
```

Когда у какого-то ID меняется состояние, backend отправляет сообщение по WebSocket, и строка на странице обновляется.

Если браузер потерял связь, таблица может временно показывать устаревшие данные. После повторного соединения frontend запрашивает актуальный список.

## 6. Что означают настройки .env

Файл `.env` находится в корне **frontend**. Он нужен для настройки адресов, на которые React обращается.

| Переменная | Объяснение |
| --- | --- |
| `REACT_APP_API_URL` | Адрес backend для обычных HTTP-запросов |
| `REACT_APP_WS_URL` | Адрес WebSocket backend для обновлений в реальном времени |

По умолчанию в `main` код также рассчитан на backend по адресу `localhost:5000`.

Если меняете `.env`, **остановите и заново запустите `npm start`**, иначе новое значение может не примениться.

**Не записывайте секретные токены в frontend-переменные.** Код frontend и настройки `REACT_APP_*` включаются в браузерную сборку и доступны пользователю.

## 8. Полезные команды

Выполняйте их, находясь **в папке `status-monitor-frontend`**:

| Команда | Что делает |
| --- | --- |
| `npm install` | Устанавливает библиотеки |
| `npm start` | Запускает локальный сервер для разработки на порту 3000 |
| `npm run build` | Собирает готовые файлы сайта в папку `build/` |
| `git status` | Показывает текущую ветку и локальные изменения |
| `git pull origin main` | Загружает и применяет изменения ветки main |

**`npm run build` не запускает опубликованный сайт.** Он только создаёт статические файлы. В ветке `main` для локальной разработки используется `npm start`; для публикации сборку нужно будет отдельно обслуживать веб-сервером.

Обновление с GitHub:

```bash
git switch main
git pull origin main
npm install
npm start
```

Если Git сообщает о незакоммиченных изменениях, сначала разберитесь с ними, чтобы случайно не потерять собственный код. Backend обновляется **отдельно в его папке**.

## 9. Если что-то не работает

| Проблема | Что проверить |
| --- | --- |
| `npm` не найден | Установлен ли Node.js, открыли ли терминал заново? |
| Не запускается frontend | Выполняли ли `npm install`? Находитесь ли в папке frontend? |
| Порт `3000` уже занят | Возможно, другой процесс или второй экземпляр сайта уже запущен |
| Страница открылась, но данных нет | Работает ли backend? Открывается ли `localhost:5000/api/health`? |
| Таблица пуста без ошибок | Отправьте тестовые события командой `npm run test:webhook` в папке backend |
| Ошибка CORS в консоли браузера | Проверьте адрес frontend и параметр `FRONTEND_ORIGIN` в backend `.env` |
| Соединение WebSocket потеряно | Проверьте backend, адрес `REACT_APP_WS_URL` и доступность порта 5000 |
| Открываете сайт с телефона, а он не получает данные | `localhost` на телефоне означает **телефон**, а не ваш компьютер; нужны сетевые адреса и настройки доступа |

## 10. Чем ветка main отличается от docker

- **`main`**: для разработки запускаются два процесса, backend на порту 5000 и React на порту 3000.
- **[`docker`](https://github.com/FoKuStNiK/status-monitor-frontend/tree/docker)**: отдельная версия развёртывания с Docker. Порядок сборки и запуска описан в README этой ветки.

Для первого знакомства с React и сервером начните с `main`, чтобы увидеть, за что отвечает каждая часть системы.
